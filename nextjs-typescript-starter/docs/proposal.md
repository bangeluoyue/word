# H5 英语单词学习项目需求文档

> 文档版本：v1.0  
> 更新时间：2026-09-13  
> 项目目录：`nextjs-typescript-starter`  
> 产品阶段：MVP

## 1. 项目概述

### 1.1 项目背景

建设一个面向移动端浏览器的英语单词学习 H5。用户可浏览全部单词书，登录后选择单词书并以卡片形式逐词学习；系统保存各单词书的学习进度，使用户下次能够从最近已学单词的下一词继续学习。

### 1.2 产品目标

- 让用户快速找到并进入合适的单词书。
- 用信息精简的单词卡降低连续学习的操作成本。
- 保存账号维度的学习进度，支持跨会话继续学习。
- 在单词详情页提供完整释义、例句、短语等扩展信息。
- 复用项目已有的邮箱、密码认证和密码哈希逻辑。

### 1.3 MVP 不包含

- 第三方账号登录、验证码登录、找回或重置密码。
- 单词搜索、收藏、生词本、拼写测试、复习算法和每日任务。
- 排行榜、社交分享、会员或付费能力。
- 音频播放。数据中的 `ukspeech`、`usspeech` 仅为资源标识，当前未提供可播放音频的基础地址。
- 后台单词书管理。本期默认读取项目内或服务端已有的单词书 JSON 数据。

## 2. 用户与核心场景

### 2.1 用户状态

| 用户状态 | 可浏览单词书 | 可进入学习 | 可查看个人进度 | 可退出登录 |
| --- | --- | --- | --- | --- |
| 未登录 | 是 | 否，点击书卡后引导登录/注册 | 否 | 否 |
| 已登录 | 是 | 是 | 是 | 是 |

### 2.2 核心用户故事

1. 作为游客，我可以浏览所有单词书，以便了解可学习的内容。
2. 作为游客，我点击单词书后会进入“我的”并看到登录弹窗，以便完成登录或注册。
3. 作为已登录用户，我可以看到最近学习的单词书并继续学习。
4. 作为已登录用户，我可以进入任意单词书；首次从第一个单词开始，再次进入时从最近已完成单词的下一词开始。
5. 作为学习中的用户，我可以点击“下一个”切换单词，并同步保存进度。
6. 作为学习中的用户，我可以点击单词进入详情页，查看完整学习资料。
7. 作为已登录用户，我可以在“我的”查看邮箱、退出登录并查看每本书的学习进度。

## 3. 信息架构与路由

| 页面 | 建议路由 | 登录要求 | 底部 Tab |
| --- | --- | --- | --- |
| 首页 | `/` | 否 | 显示，“首页”选中 |
| 我的 | `/mine` | 否 | 显示，“我的”选中 |
| 单词学习 | `/learn/[bookId]` | 是 | 不显示 |
| 单词详情 | `/word/[wordId]?bookId=...` | 是 | 不显示 |

说明：

- 底部主导航仅包含“首页”和“我的”两个 Tab，并固定在 H5 视口底部。
- 学习页和详情页属于沉浸式二级页面，顶部提供返回按钮，不显示底部 Tab。
- 未登录用户直接访问受保护路由时，统一重定向至 `/mine?auth=login&returnTo=原地址`，随后自动打开登录弹窗。
- 当前模板 `auth.config.ts` 中“已登录用户访问任意非 `/protected` 页面时跳转 `/protected`”的规则必须调整，否则登录用户无法访问本产品页面。

## 4. 核心业务流程

### 4.1 游客从单词书发起学习

```text
首页浏览单词书
      │
      ▼
点击某本单词书
      │
      ▼
跳转“我的”页面并打开登录弹窗
      │
      ├── 登录/注册成功 ──► 自动进入刚才点击的单词书
      │
      └── 关闭弹窗 ──────► 停留在“我的”未登录态
```

### 4.2 已登录用户学习

```text
点击“继续学习”或任意单词书
      │
      ▼
读取该用户在该书的学习进度
      │
      ├── 无进度 ────────► 展示第 1 个单词
      ├── 未学完 ────────► 展示最近已学单词的下一个
      └── 已完成 ────────► 展示完成页，可选择重新学习
                                │
单词卡 ──点击单词──► 单词详情 ──返回──┘
   │
点击“下一个”
   │
保存当前单词为已学并展示下一词
   │
最后一词点击“完成学习”后进入完成页
```

## 5. 全局 UI 与交互规范

### 5.1 H5 布局

- 以 375 px 宽度为主要设计基准，兼容 320–480 px 常见移动端宽度。
- 页面主体在宽屏环境下居中显示，建议最大宽度为 480 px。
- 首页和“我的”的内容底部须预留“底部 Tab 高度 + `safe-area-inset-bottom`”，避免内容被遮挡。
- 底部 Tab 点击热区不小于 44 × 44 px；主要按钮高度不小于 44 px。
- 固定区域需适配 iOS 安全区；软键盘弹起时，认证弹窗内容应能滚动，提交按钮不能被遮挡。

### 5.2 通用状态

- 加载中：列表、最近学习和进度区域显示骨架屏；提交按钮显示加载状态并禁止重复提交。
- 空数据：没有单词书时显示“暂无单词书，请稍后再来”，不显示无效空卡片。
- 请求失败：当前模块显示错误提示和“重新加载”按钮，页面其余可用内容不受影响。
- 图片失败：书籍封面使用统一默认封面，不显示破图。
- 可选词典字段缺失：直接隐藏对应模块，不展示空标题、`null` 或占位符。

### 5.3 底部 Tab

- 两个 Tab 等宽排列：左侧“首页”，右侧“我的”。
- 每项由图标和文字组成，选中项使用主色，未选中项使用中性灰。
- 点击当前 Tab 时保持当前页；从其他页点击时切换页面。

- 顶部展示产品名称或简短欢迎语。

#### 页面内容

- 若用户存在至少一条状态为“学习中”的记录，展示“最近学习”模块。

### 6.4 登录 / 注册 Popup

#### 打开与关闭

- Popup 采用底部抽屉或居中弹层，在移动端优先使用底部抽屉。
- 默认进入“登录”模式，顶部提供“登录 / 注册”切换。
- 点击遮罩或关闭按钮可关闭；提交期间禁止关闭，避免用户误以为请求已取消。
- 弹窗关闭后清理密码和错误信息；邮箱可保留至本次页面会话结束。

#### 登录模式

- 字段：邮箱、密码。
- 邮箱提交前去除首尾空格并转为小写。
- 校验：邮箱格式有效；密码不能为空。
- 登录失败统一提示“邮箱或密码错误”，不暴露账号是否存在。
- 登录成功：关闭弹窗并刷新会话。若存在合法的站内 `returnTo`，进入目标单词书；否则停留在“我的”已登录态。

#### 注册模式

- 字段：邮箱、密码、确认密码。
- 校验：邮箱格式有效；密码 8–64 个字符；两次密码一致。
- 邮箱已注册时提示“该邮箱已注册，请直接登录”。
- 注册成功后自动使用该邮箱和密码登录，再执行与登录成功相同的跳转逻辑。
- MVP 不要求邮箱验证。

#### 与已有代码的关系

- 登录复用 `app/auth.ts` 中的 Credentials Provider、`signIn('credentials')`、`getUser` 和 `bcrypt-ts.compare`。
- 注册复用 `app/register/page.tsx` 中 `getUser` / `createUser` 的账号检查和密码哈希逻辑。
- UI 需要从现有 `/login`、`/register` 独立页面抽取为可在“我的”复用的表单组件；不能继续固定跳转到 `/protected`。
- 注册接口必须处理并发下的重复邮箱；数据库邮箱字段应为非空且唯一，仅靠注册前查询不足以保证唯一性。
- `returnTo` 只允许站内相对路径，禁止接受外部 URL，避免开放重定向。

### 6.6 单词学习页

#### 进入规则

- 新书：展示按 `wordRank` 升序后的第一个单词。
- 已开始且未完成：展示 `lastLearnedRank` 后的第一个有效单词，而不是重复展示最近已完成的单词。
- 若排名不连续，不使用简单的 `rank + 1` 查找，而是在排序结果中找下一个元素。
- 已完成：不直接清空进度，进入学习完成页。
- 词书为空或进度指向不存在的单词时，展示明确错误和“返回首页”，同时记录异常，不能白屏。

#### 单词卡展示字段

为了保持卡片简单，只展示以下内容：

| UI 内容 | JSON 字段 | 规则 |
| --- | --- | --- |
| 当前序号 | `wordRank` | 显示“第 N / 总词数 词” |
| 单词 | `content.word.wordHead` | 卡片主标题，可点击进入详情 |
| 音标 | `content.word.content.usphone`、`ukphone` | 优先显示美式；两者都有时标注“美/英”并都展示 |
| 中文释义 | `content.word.content.trans[0].tranCn` | 卡片仅显示第一条释义 |
| 英文例句 | `content.word.content.sentence.sentences[0].sContent` | 仅显示第一条例句 |
| 例句中文 | `content.word.content.sentence.sentences[0].sCn` | 与英文例句成组展示 |

卡片字段缺失时的降级规则：

- `wordHead` 缺失时回退到外层 `headWord`；两者都缺失则该条数据视为无效并记录异常。
- 美式音标缺失时显示英式音标；二者均缺失则隐藏音标行。
- `trans` 为空时显示“暂无释义”。
- `sentences` 为空时隐藏整个例句区域，卡片其余内容仍可学习。

#### 页面交互

- 点击卡片中的单词标题进入详情页。
- 点击“下一个”时，先将当前单词记为已学，再切换到下一条；保存成功前按钮显示加载态并禁止重复点击。
- 保存失败时停留在当前单词并提示“进度保存失败，请重试”，不得先跳到下一词造成前端和服务端进度不一致。
- 最后一个单词的按钮文案改为“完成学习”；点击成功后将进度标记为完成并进入完成页。
- 点击左上角返回，回到来源页面；进度仅由“下一个/完成学习”动作推进，单纯打开或离开卡片不计为已学。
- 从详情页返回时仍展示进入详情前的同一张卡片，不重复推进进度。

### 6.7 单词详情页

#### 页面内容

- 顶部返回按钮和标题“单词详情”。
- 基础信息固定靠前；其余模块按“有数据才显示”的原则排列。
- 数组字段展示全部有效条目，不只展示第一条。

#### 字段映射与顺序

详情字段根路径为 `content.word.content`。

| 顺序 | 模块 | JSON 字段 | 展示规则 |
| --- | --- | --- | --- |
| 1 | 单词 | `wordHead` | 大标题 |
| 2 | 发音 | `usphone`、`ukphone` | 分别标记“美”“英” |
| 3 | 释义 | `trans[]` | 展示 `tranCn`；`tranOther` 有值时作为英文释义 |
| 4 | 例句 | `sentence.sentences[]` | 每条展示 `sContent` 和 `sCn` |
| 5 | 短语 | `phrase.phrases[]` | 每条展示 `pContent` 和 `pCn` |
| 6 | 记忆方法 | `remMethod.val` | 标题可使用 `remMethod.desc`，默认“记忆” |
| 7 | 同近词 | `syno.synos[]` | 展示词性 `pos`、释义 `tran` 和 `hwds[].w` |
| 8 | 同根词 | `relWord.rels[]` | 按词性 `pos` 分组展示 `words[].hwd`、`words[].tran` |

以下字段本期不直接展示：

- `wordId`、`wordRank`、`bookId`：仅用于定位、排序和关联。
- `sentence.desc`、`phrase.desc`、`syno.desc`、`relWord.desc`：可作为模块默认标题，但不作为独立正文。
- `descCn`、`descOther`：为释义类型标签；MVP 仅在确有区分价值时显示。
- `ukspeech`、`usspeech`：待配置合法音频地址后再支持播放。

## 8. 数据需求

### 8.1 单词书数据

当前示例只给出了单词数据，未给出书籍元数据。为支持首页，单词书至少需要以下字段：

```ts
type WordBook = {
  bookId: string;
  name: string;
  coverUrl?: string;
  description?: string;
  grade?: string;
  publisher?: string;
  totalWords: number; // 可由有效单词数组计算
};
```

要求：

- `bookId` 全局唯一，并与单词记录外层 `bookId` 一致。
- `totalWords` 以过滤无效记录后的实际数量为准；若源数据声明值不一致，以实际数量为准并记录数据异常。
- 同一本书内 `wordId` 必须唯一；单词按 `wordRank` 升序学习。
- 首页展示书卡，书内单词无需在首页列表展开。

### 8.2 单词数据结构

页面实际使用的数据路径如下：

```ts
type WordEntry = {
  wordRank: number;
  headWord?: string;
  bookId: string;
  content: {
    word: {
      wordHead?: string;
      wordId: string;
      content: {
        usphone?: string;
        ukphone?: string;
        usspeech?: string;
        ukspeech?: string;
        trans?: Array<{
          tranCn?: string;
          tranOther?: string;
          descCn?: string;
          descOther?: string;
        }>;
        sentence?: {
          desc?: string;
          sentences?: Array<{ sContent?: string; sCn?: string }>;
        };
        phrase?: {
          desc?: string;
          phrases?: Array<{ pContent?: string; pCn?: string }>;
        };
        remMethod?: { desc?: string; val?: string };
        syno?: {
          desc?: string;
          synos?: Array<{
            pos?: string;
            tran?: string;
            hwds?: Array<{ w?: string }>;
          }>;
        };
        relWord?: {
          desc?: string;
          rels?: Array<{
            pos?: string;
            words?: Array<{ hwd?: string; tran?: string }>;
          }>;
        };
      };
    };
  };
};
```

### 8.3 用户与学习进度

现有 `User` 表可继续使用，但需保证 `email` 非空且唯一。建议新增学习进度表：

```ts
type LearningProgress = {
  id: number;
  userId: number;
  bookId: string;
  lastLearnedWordId: string | null;
  lastLearnedRank: number | null;
  learnedCount: number;
  totalWords: number;
  status: 'learning' | 'completed';
  startedAt: Date;
  updatedAt: Date;
  completedAt: Date | null;
};
```

约束与计算规则：

- `(userId, bookId)` 必须唯一，确保一个用户每本书只有一条主进度。
- 进度属于账号，不存储在仅当前设备有效的 `localStorage` 中。
- 第一次成功点击“下一个”或“完成学习”时创建进度记录。
- `learnedCount` 表示已通过按钮确认的单词数量；仅打开卡片不增加计数。
- 进度百分比为 `min(100, round(learnedCount / totalWords * 100))`。
- 推进进度需要事务或原子更新，并校验请求中的当前 `wordId`，以降低重复点击或多端并发造成的跳词风险。
- 同一个推进请求应具有幂等性：重复提交同一当前单词不能重复增加 `learnedCount`。
- 单词书内容变化导致原进度找不到下一词时，回退至排序后第一个尚未完成的有效词；不能回退时标记为完成，并记录异常供排查。

## 9. 服务端能力建议

具体使用 Route Handler 还是 Server Action 可由实现决定，但至少需要以下能力：

| 能力 | 输入 | 输出/行为 |
| --- | --- | --- |
| 获取书籍列表 | 当前用户可选 | 书籍元数据；登录时合并各书进度 |
| 获取最近学习 | 当前用户 | 状态为 `learning` 且 `updatedAt` 最新的一条进度及书籍信息；无学习中记录返回空 |
| 获取某书学习上下文 | `bookId`、当前用户 | 书籍信息、总词数、下一待学单词或已完成状态 |
| 推进学习进度 | `bookId`、当前 `wordId`、当前用户 | 原子保存进度并返回下一词或完成状态 |
| 获取单词详情 | `wordId`、`bookId` | 所属书中唯一匹配的完整单词数据 |
| 获取我的进度 | 当前用户 | 按 `updatedAt` 倒序的全部学习记录 |
| 重置某书进度 | `bookId`、当前用户 | 二次确认后清除/重置该用户该书的进度 |
| 登录/注册/退出 | 邮箱、密码等 | 创建或更新认证会话 |

所有进度接口必须从服务端会话获取 `userId`，不得信任客户端传入的用户标识。

## 11. 非功能需求

### 11.1 性能

- 首屏优先返回页面骨架与书籍列表，不因加载个人进度长时间白屏。
- 大型单词 JSON 不应全部发送到首页；学习页只加载当前学习所需数据，详情页按需加载完整内容。
- 连续切词可预取下一词，但不得在用户确认前推进服务端进度。

### 11.2 安全与隐私

- 密码必须使用现有 `bcrypt-ts` 哈希后存储，禁止明文存储、返回或写入日志。
- 服务端对邮箱和密码再次校验，不能只依赖客户端校验。
- 登录失败使用统一提示；认证接口应具备基础限流能力。
- 所有学习进度读写都要校验会话和数据归属。
- 日志和埋点中邮箱应按实际合规要求脱敏；绝不记录密码。

### 11.3 可用性与无障碍

- 文本与背景对比度应满足 WCAG AA 的基本要求。
- 图标按钮需提供可访问名称；表单标签与输入框正确关联。
- 错误提示使用 `aria-live`，提交加载态对读屏软件可感知。
- 所有核心流程可通过键盘操作；按钮不能只依赖颜色表达状态。

### 11.4 兼容性

- 支持最近两个大版本的 iOS Safari、Android Chrome 和微信内置浏览器。
- 使用动态视口单位或等价方案，避免移动浏览器地址栏导致页面高度和固定底栏异常。

## 13. 实施前数据约定

以下未在原始需求中提供，本文给出 MVP 默认约定，开发可据此推进：

1. 书籍列表必须补充 `bookId`、`name` 等元数据；若没有封面，使用统一默认封面。
2. 首页展示的是“所有单词书”，不是将每本书的所有单词直接铺在首页。
3. 最近学习模块只展示“学习中”记录里最近更新的一本书；已完成记录和全部历史进度集中在“我的”。
4. 注册成功后自动登录，以完成 Popup 内的闭环。
5. 从书卡触发登录时保留目标书，认证成功后直接进入该书；从“我的”主动登录则留在原页。
6. 音频播放暂不进入 MVP；提供音频资源基础地址后再补充发音按钮。
7. 单词详情内容以实际 JSON 为准，同一词缺少的模块直接隐藏。
