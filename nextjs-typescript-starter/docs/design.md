> 文档版本：v1.0
> 更新时间：2026-09-13

## 1. 文档目的

本文给出 H5 英语单词学习项目的前后端技术方案，重点解决以下问题：

- 在现有 Next.js、Auth.js、Drizzle 和 PostgreSQL 项目上完成首页、“我的”、认证弹窗、单词学习和详情页。
- 接入已有 `books`、`words` 表，不复制单词书和词典数据。
- 补齐用户表和学习进度表，支持账号维度的续学、完成和重新学习。
- 保证“下一个”操作原子、幂等，避免重复点击或多设备并发导致跳词。
- 将数据库 JSON 转换为稳定的前端视图模型，容忍可选字段和少量脏数据。
- 给出目录结构、模块边界、数据查询、鉴权、缓存、错误处理、测试和上线迁移方案。

本文是实现依据；页面视觉与产品验收口径以 `docs/proposal.md` 为准。

## 2. 技术基线与现状

### 2.1 现有技术栈

| 层级 | 当前技术 | 设计结论 |
| --- | --- | --- |
| Web 框架 | Next.js 14 App Router | 继续使用 Server Component、Server Action 和 Route Handler |
| 语言 | TypeScript 5，严格模式 | 继续使用；数据库 JSON 在边界处做运行时解析 |
| UI | React 18、Tailwind CSS | 继续使用；不引入全局组件库 |
| 认证 | NextAuth/Auth.js v5 beta，Credentials Provider | 复用现有邮箱密码登录，调整路由和会话类型 |
| ORM/数据库访问 | Drizzle ORM、`postgres` | 继续使用；移除请求时建表逻辑，改为正式迁移 |
| 数据库 | PostgreSQL | `books`、`words` 为词库数据源，新增用户与进度表 |
| 密码哈希 | `bcrypt-ts` | 继续使用，不允许明文密码落库 |

实现期间如升级依赖版本，需要单独验证 Auth.js Server Action 行为和 Drizzle 迁移兼容性；本期不把框架大版本升级与业务开发绑定在一起。

### 2.2 已有数据库表

当前数据库已经存在 `public.words` 和 `public.books`。

```sql
create table public.words (
  id bigint generated by default as identity not null,
  "wordRank" integer null,
  "headWord" text null,
  content json null,
  "bookId" text null,
  constraint words_pkey primary key (id)
);
```

```sql
create table public.books (
  id uuid not null default gen_random_uuid(),
  title text not null,
  word_count integer not null default 0,
  cover_url text null,
  book_id text not null,
  tags text null,
  created_at timestamp with time zone not null default now(),
  updated_at timestamp with time zone not null default now(),
  constraint books_pkey primary key (id),
  constraint books_book_id_unique unique (book_id)
);
```

字段对应关系：

| 领域含义 | 数据库字段 |
| --- | --- |
| 单词书业务 ID | `books.book_id` |
| 单词书名称 | `books.title` |
| 单词总数 | `books.word_count` |
| 单词书封面 | `books.cover_url` |
| 单词书标签 | `books.tags` |
| 单词所属书 | `words."bookId"` |
| 单词排序 | `words."wordRank"`，同排名时以 `words.id` 保证确定顺序 |
| 单词卡回退标题 | `words."headWord"` |
| 词典结构 | `words.content` JSON |

根据需求样例，本文假设 `words.content` 保存的是外层记录的 `content` 值，即 JSON 根节点为 `word`：

```text
words.content
└── word
    ├── wordHead
    ├── wordId
    └── content
        ├── usphone / ukphone
        ├── trans[]
        ├── sentence.sentences[]
        ├── phrase.phrases[]
        ├── remMethod
        ├── syno.synos[]
        └── relWord.rels[]
```

实现前必须用第 13.2 节的数据审计 SQL 验证该根路径。如果实际保存的是完整外层对象，应统一修复数据或在解析层调整一次，不能在不同页面使用两套路径。

### 2.3 现有认证代码需要调整的部分

当前代码具备可复用的认证基础，但不能原样用于本产品：

- `app/db.ts` 在请求期间通过 `ensureTableExists()` 创建 `"User"` 表；生产设计应改为部署前数据库迁移。
- `app/auth.config.ts` 会把已登录用户访问的所有非 `/protected` 页面重定向到 `/protected`；这会阻止用户访问首页、“我的”和学习页面。
- `app/login/page.tsx` 登录成功固定跳转 `/protected`；应改为认证弹窗并支持安全的 `returnTo`。
- `app/register/page.tsx` 注册成功跳转独立登录页；本产品要求注册成功后自动登录。
- 现有注册逻辑先查询再插入，但数据库邮箱没有唯一约束，存在并发重复注册风险。
- 现有 `Form` 只有邮箱和密码，需要支持登录/注册模式、确认密码和字段级错误。

## 3. 总体架构

### 3.1 架构原则

1. 读操作优先放在 Server Component/服务端查询中，避免浏览器直接连接数据库。
2. 认证、推进进度、重置进度等写操作使用 Server Action，并在服务端再次校验会话和输入。
3. 词典 JSON 只能由数据映射层解析，页面组件不直接读取深层 JSON 路径。
4. 公共词库数据和用户数据分开缓存；任何带 `userId` 的查询不进入共享缓存。
5. 学习进度以服务端为准，客户端只保存当前展示状态，不用 `localStorage` 作为持久化源。
6. 所有数据库结构变化通过版本化迁移完成，不在页面请求中自动建表或改表。

### 3.3 渲染边界

| 模块 | 类型 | 原因 |
| --- | --- | --- |
| 首页页面、书籍列表初始数据 | Server Component | 直接读取会话和数据库，减少客户端请求瀑布 |
| “我的”页面、进度初始数据 | Server Component | 用户数据在服务端鉴权后获取 |
| 学习页初始单词 | Server Component | 进入页面前确定正确续学位置 |
| 单词详情初始数据 | Server Component | 仅加载当前单词完整 JSON |
| 底部 Tab | 默认 Server Component + `Link` | 无复杂状态；选中态可由布局或小型 Client Component 处理 |
| AuthPopup/AuthForm | Client Component | 需要模式切换、表单状态、弹层和键盘交互 |
| WordCardControls | Client Component | 需要提交“下一个”并即时替换卡片 |
| LogoutConfirm/RestartConfirm | Client Component | 需要本地确认弹窗状态 |

## 5. 数据库设计

### 5.1 表关系

```text
"User" 1 ─────────── N learning_progress N ─────────── 1 books
                              │
                              │ last_word_row_id（可空）
                              ▼
                            words N ─────────────────── 1 books
                                  words."bookId" = books.book_id
```

本期新增或正式纳管两张业务相关表：

1. `"User"`：沿用当前认证代码的表名，保存邮箱和密码哈希。
2. `learning_progress`：每个用户、每本书一条连续学习进度。

MVP 不新增“每个用户 × 每个单词”的明细表。产品只要求按固定顺序连续学习和续学，`learning_progress` 的游标与计数已经足够；为每次点击插入明细会显著增加数据量，却不能带来当前功能收益。如果以后增加生词本、熟练度、遗忘曲线或逐词复习，再新增 `user_word_state`，不要提前把它混入当前主流程。

### 5.2 用户表目标结构

当前 `app/db.ts` 使用大小写敏感的 `public."User"`。为降低认证改造风险，本期保留该表名，但将结构正式迁移并加上数据完整性约束。

```sql
create table public."User" (
  id serial primary key,
  email varchar(254) not null,
  password varchar(255) not null,
  created_at timestamp with time zone not null default now(),
  updated_at timestamp with time zone not null default now()
);

create unique index user_email_lower_unique
  on public."User" (lower(email));
```

设计说明：

- `password` 列只保存 bcrypt 哈希。保留旧列名是为了兼容当前代码；领域代码中应命名为 `passwordHash`，避免误用。
- 邮箱写入前执行 `trim().toLowerCase()`；数据库使用 `lower(email)` 唯一索引作为最终并发保护。
- 注册时捕获 PostgreSQL 唯一冲突码 `23505` 并转换为“该邮箱已注册”，不能只依赖插入前查询。
- 无数据库 Adapter 的 Credentials/JWT 会话不需要 `Account`、`Session`、`VerificationToken` 表。
- 若未来切换 Auth.js 数据库 Adapter，再通过独立迁移补齐其标准表，不能与学习进度表耦合。

### 5.3 学习进度表

```sql
create table public.learning_progress (
  id bigint generated by default as identity primary key,
  user_id integer not null,
  book_id text not null,
  last_word_row_id bigint null,
  last_word_rank integer null,
  learned_count integer not null default 0,
  total_words integer not null,
  status text not null default 'learning',
  version integer not null default 0,
  started_at timestamp with time zone not null default now(),
  updated_at timestamp with time zone not null default now(),
  completed_at timestamp with time zone null,

  constraint learning_progress_user_fk
    foreign key (user_id)
    references public."User" (id)
    on delete cascade,

  constraint learning_progress_book_fk
    foreign key (book_id)
    references public.books (book_id)
    on update cascade
    on delete cascade,

  constraint learning_progress_last_word_fk
    foreign key (last_word_row_id)
    references public.words (id)
    on delete set null,

  constraint learning_progress_user_book_unique
    unique (user_id, book_id),

  constraint learning_progress_status_check
    check (status in ('learning', 'completed')),

  constraint learning_progress_count_check
    check (
      total_words > 0
      and learned_count >= 0
      and learned_count <= total_words
    ),

  constraint learning_progress_rank_check
    check (
      (learned_count = 0 and last_word_rank is null)
      or (learned_count > 0 and last_word_rank is not null)
    ),

  constraint learning_progress_completion_check
    check (
      (
        status = 'learning'
        and learned_count < total_words
        and completed_at is null
      )
      or
      (
        status = 'completed'
        and learned_count = total_words
        and completed_at is not null
      )
    )
);

create index learning_progress_user_updated_idx
  on public.learning_progress (user_id, updated_at desc);

create index learning_progress_recent_learning_idx
  on public.learning_progress (user_id, updated_at desc)
  where status = 'learning';
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `user_id` | 当前进度所属用户，只能从服务端会话获得 |
| `book_id` | 单词书业务 ID，对应 `books.book_id` |
| `last_word_row_id` | 最近一次由“下一个/完成学习”确认的 `words.id`，不是 JSON 内的 `wordId` |
| `last_word_rank` | 最近确认单词的排名，用于寻找下一有效词和删除后的降级 |
| `learned_count` | 已经由用户确认完成的连续单词数量 |
| `total_words` | 开始学习时该书有效单词数快照 |
| `status` | `learning` 或 `completed` |
| `version` | 每次推进或重置时加一，用于检测陈旧客户端状态 |
| `started_at` | 首次成功推进该书的时间；重新学习时重置 |
| `updated_at` | 最近推进或重置时间，也是“最近学习”的排序字段 |
| `completed_at` | 全书完成时间，学习中必须为空 |

`last_word_row_id` 外键只能保证单词存在，不能保证该单词属于同一本 `book_id`；推进服务必须显式校验 `words."bookId" = learning_progress.book_id`。

### 5.4 为什么保存总词数快照

`books.word_count` 是目录数据，`learning_progress.total_words` 是用户开始本次学习时的快照。快照有三个作用：

- “已学数/总数”和完成状态在同一次学习周期内保持一致。
- 避免每次展示“我的”都对 `words` 做聚合计数。
- 数据导入异常时可以发现 `books.word_count` 与有效单词数不一致。

MVP 约定：已发布书籍的 `book_id`、有效单词集合和顺序不可原地修改；修订版使用新的 `book_id`。如果必须修改已发布书，需先设计进度迁移策略，不能直接覆盖导致已完成用户变回学习中。

### 5.5 现有 books/words 表补强

在数据审计通过后，建议增加以下约束和索引：

```sql
alter table public.books
  add constraint books_word_count_nonnegative
  check (word_count >= 0);

alter table public.words
  add constraint words_book_fk
  foreign key ("bookId")
  references public.books (book_id)
  on update cascade
  on delete cascade;

alter table public.words
  add constraint words_rank_positive
  check ("wordRank" is null or "wordRank" > 0);

create index words_book_rank_id_idx
  on public.words ("bookId", "wordRank", id);

create unique index words_book_word_id_unique
  on public.words (
    "bookId",
    ((content -> 'word' ->> 'wordId'))
  )
  where
    "bookId" is not null
    and nullif(btrim(content -> 'word' ->> 'wordId'), '') is not null;
```

是否立即将 `words."bookId"`、`"wordRank"` 和 `content` 改为 `NOT NULL`，取决于审计结果。推荐先清理脏数据，再分阶段加非空约束；不要让一次约束迁移因历史数据中断整个上线。

不强制把 `json` 改为 `jsonb`：MVP 主要按 `bookId`、`wordRank` 和提取的 `wordId` 查询，不做任意 JSON 包含检索。未来需要复杂 JSON 搜索时再评估 `jsonb` 和 GIN 索引，避免无收益的整表重写。

### 5.6 单词排序与有效性

有效学习单词至少满足：

- `words."bookId"` 与存在的 `books.book_id` 匹配。
- `words."wordRank"` 为大于 0 的整数。
- `words.content -> 'word' ->> 'wordId'` 去除首尾空格后非空。
- `wordHead` 或外层 `headWord` 至少一个去除首尾空格后非空。

确定排序统一使用：

```sql
order by "wordRank" asc, id asc
```

即使导入数据意外出现重复排名，`id` 也能保证服务端和前端看到相同顺序。数据导入流程仍应把同一本书内的重复排名视为错误并报警。

### 5.7 Drizzle schema 约定

- 在 `lib/db/schema.ts` 集中声明 `books`、`words`、`users`、`learningProgress`，不得由 repository 临时定义表。
- `words.content` 在数据库行类型中声明为 `unknown` 或宽松 JSON 类型，读取后交给运行时 schema 解析。
- TypeScript 属性使用 camelCase，数据库列显式映射原名，例如 `wordRank: integer('wordRank')`。
- `learning_progress.status` 在 TypeScript 中收窄为 `'learning' | 'completed'`。
- 数据库时间统一使用 `timestamptz`，服务端以 `Date` 处理，传给客户端后使用 ISO 8601 字符串。
- 迁移文件必须提交到仓库；应用启动和页面请求不能调用 `CREATE TABLE`。

## 6. 数据模型与 JSON 映射

### 6.1 分层模型

避免一个类型同时承担数据库、业务和 UI 三种职责：

```text
WordRow（数据库行，content: unknown）
          │ 运行时校验 + 清理
          ▼
WordDomain（完整、可选字段已规范化）
          ├──────────────► WordCardViewModel（首条释义、首条例句）
          └──────────────► WordDetailViewModel（全部有效模块）
```

建议增加兼容当前依赖版本的运行时校验库，例如 Zod。若不增加依赖，也必须实现等价的类型守卫，不能对数据库 JSON 直接做未经检查的类型断言。

### 6.2 领域类型

```ts
export type WordDomain = {
  rowId: string; // bigint 跨 RSC 边界时序列化为字符串
  bookId: string;
  rank: number;
  wordId: string;
  headword: string;
  pronunciations: {
    us?: string;
    uk?: string;
    usSpeechKey?: string;
    ukSpeechKey?: string;
  };
  translations: Array<{
    chinese?: string;
    english?: string;
    chineseLabel?: string;
    englishLabel?: string;
  }>;
  sentences: Array<{ english?: string; chinese?: string }>;
  phrases: Array<{ english?: string; chinese?: string }>;
  memoryMethod?: string;
  synonyms: Array<{
    partOfSpeech?: string;
    translation?: string;
    words: string[];
  }>;
  relatedWords: Array<{
    partOfSpeech?: string;
    words: Array<{ headword?: string; translation?: string }>;
  }>;
};
```

规则：

- `rowId` 使用字符串传到客户端，防止 JavaScript `number` 无法安全表示 PostgreSQL `bigint`。
- 所有字符串执行 `trim()`；空字符串归一化为 `undefined` 并在数组中剔除无内容项。
- `headword = content.word.wordHead || words.headWord`。
- 音标不自动添加或删除 `/`，由展示组件统一包裹，避免源数据出现双斜线。
- 无效的可选模块只隐藏；缺少 `bookId/rank/wordId/headword` 的核心记录不进入学习序列并记录结构化错误。

### 6.3 卡片视图模型

```ts
export type WordCardViewModel = {
  rowId: string;
  bookId: string;
  wordId: string;
  rank: number;
  ordinal: number;
  totalWords: number;
  headword: string;
  usPhone?: string;
  ukPhone?: string;
  primaryTranslation: string;
  example?: {
    english?: string;
    chinese?: string;
  };
};
```

映射要求：

- `primaryTranslation` 取第一条非空 `tranCn`；没有时使用“暂无释义”。
- `example` 只取第一条至少有一侧内容的例句。
- `ordinal` 是有效排序中的位置，不直接假设等于 `wordRank`；页面显示“第 ordinal / totalWords 词”。
- 顺序学习时 `ordinal = learnedCount + 1`；首次为 1，成功推进后下一张为更新后的 `learnedCount + 1`，因此不需要为每张卡额外统计前置行。
- 卡片不携带短语、同根词等大数组，减少 RSC 传输和客户端内存。

### 6.4 详情视图模型

详情模型包含全部有效 `translations/sentences/phrases/synonyms/relatedWords` 和 `memoryMethod`。组件按产品文档规定的顺序渲染；空数组对应模块完全不渲染。

详情查询必须同时使用 `bookId` 和 JSON 中的 `wordId`，避免不同书中相同业务词 ID 导致歧义：

```sql
select id, "wordRank", "headWord", content, "bookId"
from public.words
where "bookId" = $1
  and content -> 'word' ->> 'wordId' = $2
limit 1;
```

### 7.3 下一有效单词查询

首次进入：

```sql
select id, "wordRank", "headWord", content, "bookId"
from public.words
where "bookId" = $1
  and "wordRank" is not null
  and "wordRank" > 0
  and nullif(btrim(content -> 'word' ->> 'wordId'), '') is not null
  and coalesce(
    nullif(btrim(content -> 'word' ->> 'wordHead'), ''),
    nullif(btrim("headWord"), '')
  ) is not null
order by "wordRank" asc, id asc
limit 1;
```

正常续学时，在同一确定排序上查找下一行：

```sql
select id, "wordRank", "headWord", content, "bookId"
from public.words
where "bookId" = $1
  and "wordRank" is not null
  and "wordRank" > 0
  and nullif(btrim(content -> 'word' ->> 'wordId'), '') is not null
  and coalesce(
    nullif(btrim(content -> 'word' ->> 'wordHead'), ''),
    nullif(btrim("headWord"), '')
  ) is not null
  and ("wordRank", id) > ($2, $3)
order by "wordRank" asc, id asc
limit 1;
```

若 `last_word_row_id` 因词库维护被置空，只能用 `last_word_rank` 回退查找排名更大的词。由于这种降级无法精确处理重复排名，应记录告警；正式数据约束应阻止已发布词库删除或重排。

## 8. 学习进度核心算法

### 8.1 状态定义

| 数据状态 | 含义 | 进入学习页行为 |
| --- | --- | --- |
| 无进度记录 | 用户尚未确认学完该书任何单词 | 展示第一有效词 |
| `learning` | 已确认至少一词，尚有下一词 | 展示最近确认词之后的下一有效词 |
| `completed` | 最后一有效词已经确认 | 展示完成页 |

仅浏览第一张卡片不创建进度。用户第一次成功点击“下一个”或“完成学习”时，在事务中创建记录并确认当前词。

### 8.2 推进动作契约

```ts
type AdvanceWordInput = {
  bookId: string;
  currentWordRowId: string;
  progressVersion?: number;
};

type AdvanceWordResult =
  | {
      ok: true;
      state: 'next';
      progress: ProgressViewModel;
      nextWord: WordCardViewModel;
    }
  | {
      ok: true;
      state: 'completed';
      progress: ProgressViewModel;
    }
  | {
      ok: false;
      code: 'AUTH_REQUIRED' | 'INVALID_INPUT' | 'NOT_FOUND' |
            'PROGRESS_CONFLICT' | 'DATABASE_ERROR';
      message: string;
      current?: WordCardViewModel;
    };
```

客户端不能传 `userId`、`learnedCount`、`lastWordRank` 或 `status`；这些值全部由服务端会话和数据库计算。

### 8.3 原子推进流程

```text
advanceWord(bookId, currentWordRowId)
  1. 从服务端 session 读取 userId；无会话直接失败
  2. 校验 bookId 和 bigint 字符串格式
  3. 开启数据库事务
  4. 校验单词书存在
  5. SELECT ... FOR UPDATE 读取该用户、该书的进度
     └─ 如无进度，才计算有效总词数，使用 ON CONFLICT DO NOTHING 初始化，
        随后重新 SELECT ... FOR UPDATE（处理并发首次推进）
  6. 后续推进使用进度中的 total_words 快照，不在每次点击重新 count 全书
  7. 根据锁定后的游标计算服务端期望展示的当前单词
  8. 校验客户端 currentWordRowId
     ├─ 等于期望当前词：允许推进
     ├─ 等于已记录的 last_word_row_id：视为相邻重复请求，返回当前服务端状态
     └─ 其他：返回 PROGRESS_CONFLICT，不修改数据
  9. 查询当前词之后的下一有效词
 10. 更新 last_word_row_id/rank、learned_count、version、updated_at
 11. 无下一词时同时写 status=completed、completed_at、learned_count=total_words
 12. 提交事务
 13. 返回下一张精简卡片或完成状态
```

关键 SQL 需要采用条件更新或行锁；不能执行“先读进度、事务外算加一、再无条件写回”。`READ COMMITTED + SELECT FOR UPDATE` 已能满足该单行串行推进场景。

步骤 4–11 任一校验失败都必须回滚事务，包括回滚尚未完成首次推进的初始化行；相邻重复请求是例外，它不更新数据，只读取并返回已经提交的服务端状态。

### 8.4 幂等与多端冲突

典型重复点击：

```text
设备请求 A：当前词 = pencil ──► 成功，last = pencil，返回 ruler
设备请求 B：当前词 = pencil ──► 锁后发现 last 已是 pencil
                               └─► 不再 +1，直接返回 ruler
```

如果设备 B 落后多个单词，提交的词既不是服务端期望当前词，也不是刚确认的 `last_word_row_id`，返回 `PROGRESS_CONFLICT` 和服务端当前卡片。客户端提示“学习进度已在其他设备更新”，然后切换到服务端卡片。

`version` 用于辅助发现陈旧状态和日志诊断，但幂等不能只依赖客户端版本号；最终仍以事务内的当前词校验为准。

### 8.5 重新学习

`restartBookAction(bookId)` 必须要求登录并在用户二次确认后调用。事务内执行：

```sql
update public.learning_progress
set
  last_word_row_id = null,
  last_word_rank = null,
  learned_count = 0,
  total_words = $current_valid_total,
  status = 'learning',
  version = version + 1,
  started_at = now(),
  updated_at = now(),
  completed_at = null
where user_id = $user_id
  and book_id = $book_id;
```

更新后返回第一有效词。书为空时不修改原完成进度并返回 `BOOK_EMPTY` 类型的业务错误。

## 9. 服务端设计

### 9.1 页面查询

#### 首页 `/`

1. 调用 `auth()`，会话可空。
2. 未登录只查询书籍目录。
3. 已登录查询书籍与该用户进度，并选出最近一条 `learning` 记录。
4. 将结果映射为 `BookCardViewModel[]` 和可空 `RecentLearningViewModel`。
5. Server Component 渲染首屏；书卡点击目标根据会话决定。

#### 我的 `/mine`

1. 调用 `auth()`。
2. 未登录渲染未登录态；根据安全解析后的 `auth=login` 决定是否初始打开 Popup。
3. 已登录查询用户全部进度并渲染账号卡和列表。
4. `returnTo` 只传给认证表单，不直接用于服务端重定向。

#### 学习 `/learn/[bookId]`

1. 必须登录，否则重定向到 `/mine?auth=login&returnTo=...`。
2. 校验并解码 `bookId`。
3. 并行查询书籍与用户进度。
4. 无进度时加载第一词；`learning` 时加载下一词；`completed` 时加载完成模型。
5. 单词书不存在返回 `notFound()`；书存在但无有效单词显示业务空状态。

#### 详情 `/word/[wordId]?bookId=...`

1. 必须登录。
2. `bookId` 和 `wordId` 都必须存在且长度受限。
3. 用两者查找唯一记录并解析完整 JSON。
4. 找不到或核心数据无效时返回 404/错误状态。
5. 返回链接优先依赖浏览器历史；同时提供 `/learn/[bookId]` 作为无历史记录时的后备路径。

### 9.2 Server Actions

MVP 不额外暴露公共 REST API：页面读取由 Server Component 直接调用服务层，浏览器写入由 Server Action 完成，认证仍使用现有 `/api/auth/[...nextauth]`。这样能减少重复的 HTTP DTO 和客户端缓存层。如果后续需要原生 App 或第三方客户端，再在同一 service 之上增加版本化 Route Handler，不能复制进度算法。

| Action | 权限 | 事务 | 成功后行为 |
| --- | --- | --- | --- |
| `registerAction` | 游客 | 用户插入 | 创建账号、自动登录、返回安全目标 |
| `advanceWordAction` | 登录 | 必须 | 返回下一卡片或完成状态 |
| `restartBookAction` | 登录 | 必须 | 重置并返回第一卡片 |
| `signOutAction` | 登录 | Auth.js 会话操作 | 清会话，停留 `/mine` |

登录继续调用 Auth.js `signIn('credentials', ...)`。如果所用 Auth.js beta 版本在 Server Action 中通过抛出 redirect 完成跳转，Action 边界必须重新抛出框架重定向异常，不能将其误转为“登录失败”。

统一返回结构：

```ts
export type ActionResult<T> =
  | { ok: true; data: T }
  | {
      ok: false;
      code: string;
      message: string;
      fieldErrors?: Record<string, string[]>;
    };
```

用户可见消息使用稳定中文文案；数据库错误、堆栈和 SQL 不返回客户端。

### 9.3 认证配置

#### Credentials authorize

- 对输入进行运行时校验；邮箱 `trim + lowercase`。
- 按规范化邮箱查询 `"User"`。
- 用户不存在和密码不匹配都返回同一个认证失败结果。
- 使用 `bcrypt-ts.compare` 比较哈希。
- 返回最小用户对象 `{ id: String(user.id), email: user.email }`。

#### JWT 与 session

当前 Credentials 模式不配置数据库 Adapter，继续使用 JWT session。通过 Auth.js callback 把 `token.sub` 映射到 `session.user.id`，并增加 TypeScript 模块声明，使服务层无需 `any`。

```ts
declare module 'next-auth' {
  interface Session {
    user: {
      id: string;
      email: string;
    };
  }
}
```

服务端使用前仍将 `session.user.id` 校验并转换为安全整数。

#### Middleware

中间件只处理页面级导航体验：

- `/learn/:path*` 和 `/word/:path*` 未登录时跳转“我的”认证弹窗。
- `/`、`/mine` 始终允许访问。
- 已登录用户访问 `/`、`/mine` 时不重定向 `/protected`。
- Server Action 和数据服务仍必须调用 `auth()`；不能把 middleware 当作唯一权限边界。

原 `/protected`、`/login`、`/register` 页面在新流程稳定后可删除或改为兼容重定向：

- `/login` → `/mine?auth=login`
- `/register` → `/mine?auth=register`
- `/protected` → `/mine`

### 9.4 安全 returnTo

允许格式：以单个 `/` 开头的站内相对路径，例如 `/learn/PEPXiaoXue3_1`。

拒绝格式：

- `https://...`、`http://...`
- `//evil.example.com`
- 包含控制字符的值
- 超过合理长度的值
- 非允许业务路由

建议只允许 `/learn/` 和 `/word/` 前缀；解析失败统一回退 `/mine`。`returnTo` 应先构造、再使用 `URLSearchParams` 编码，禁止字符串拼接。

### 9.5 输入校验

| 输入 | 服务端规则 |
| --- | --- |
| 邮箱 | 去空格、转小写、合法邮箱格式、最长 254 字符 |
| 登录密码 | 非空、设置请求体合理上限 |
| 注册密码 | 8–64 个字符 |
| 确认密码 | 必须与注册密码相同，不落库 |
| `bookId` | 非空字符串、建议最长 128、数据库中必须存在 |
| `wordId` | 非空字符串、建议最长 256，并与 `bookId` 联合查找 |
| `currentWordRowId` | 仅由十进制数字组成、可安全转换为 PostgreSQL bigint 字符串 |
| `progressVersion` | 可选非负整数 |

客户端校验只提升体验，服务端校验才是安全边界。

### 9.6 限流与安全日志

- 登录和注册按 IP + 规范化邮箱进行基础限流；具体存储可使用部署平台 KV/Redis。单实例开发环境可以内存实现，但生产不能依赖进程内 Map。
- 登录失败日志不记录密码，也不区分对外提示；内部可记录匿名化用户键、请求 ID 和失败分类。
- 进度写入日志包含 `requestId/userId/bookId/currentWordRowId/oldVersion/newVersion/result`。
- 所有 SQL 使用 Drizzle 或 `postgres` 参数化模板，禁止拼接路由参数。

## 10. 前端设计

### 10.1 状态管理策略

本期不引入 Redux、Zustand 等全局状态库：

- 登录态：Auth.js session，由 Server Component 读取。
- 书籍和进度：服务端数据，导航或 `router.refresh()` 后刷新。
- Auth Popup 开关与模式：URL 查询参数提供可恢复初始状态，组件本地状态负责交互。
- 当前单词卡：学习页初始由服务端提供；点击“下一个”后用 Action 返回值更新局部状态。
- 表单错误和 pending：React 表单状态能力与 `useFormStatus`。

这样可以避免客户端缓存与数据库进度出现双重真相。

### 10.2 主布局与底部 Tab

`app/(main)/layout.tsx` 提供最大宽度、背景、内容底部留白和固定 Tab。建议结构：

```tsx
<div className="mx-auto min-h-dvh max-w-[480px] bg-white">
  <main className="pb-[calc(64px+env(safe-area-inset-bottom))]">
    {children}
  </main>
  <BottomTabs />
</div>
```

- 首页根路由位于 `(main)` 路由组，不影响实际 URL。
- 学习路由位于独立 `(learning)` 布局，不继承底部 Tab。
- 使用 `min-h-dvh` 或兼容降级处理移动浏览器动态地址栏。
- Tab 使用真实链接，保留浏览器返回能力和无 JavaScript 基础导航。

### 10.3 首页组件

```text
HomePage (Server)
├── PageHeader
├── RecentLearningCard? (仅登录且有 learning 进度)
└── BookList
    └── BookCard[]
```

`BookCard` 点击规则：

```ts
const href = isLoggedIn
  ? `/learn/${encodeURIComponent(book.bookId)}`
  : `/mine?auth=login&returnTo=${encodeURIComponent(
      `/learn/${encodeURIComponent(book.bookId)}`,
    )}`;
```

实际实现应使用 `URLSearchParams` 生成查询字符串。封面使用 Next.js Image 时，需要配置合法远程域名；若域名不可控或 URL 无效，使用本地默认封面。

### 10.4 Auth Popup

组件状态：

```ts
type AuthMode = 'login' | 'register';

type AuthPopupState = {
  open: boolean;
  mode: AuthMode;
  retainedEmail: string;
};
```

交互要求：

- 初始模式来自 `auth=login|register`，非法值使用 `login`。
- 弹窗打开时锁定背景滚动，将焦点移到标题或邮箱输入框。
- Tab 切换时保留邮箱、清空密码和服务端错误。
- 关闭时恢复触发按钮焦点；通过书卡自动打开时恢复到页面主标题。
- 提交 pending 时禁用提交和模式切换，避免重复请求。
- 错误摘要使用 `aria-live="polite"`；字段使用 `aria-invalid` 和 `aria-describedby`。
- 登录成功有 `returnTo` 时导航目标；无目标时关闭弹窗并 `router.refresh()`。

注册 Action 可以内部完成创建用户和自动登录。密码无需存入 React 全局状态或 URL，Action 完成后立即清理。

### 10.5 我的页面

```text
MinePage (Server)
├── GuestPanel + AuthPopup               # 未登录
└── AccountCard + ProgressList           # 已登录
                    └── ProgressCard[]
```

- 登出按钮先显示客户端确认框，再提交 Auth.js `signOut` Action。
- 退出后回到 `/mine`，清理 `auth` 和 `returnTo` 查询参数。
- 进度卡的百分比、状态和目标链接由服务端 ViewModel 给出，组件不重复推导业务规则。
- 无进度时渲染稳定空状态，不发起额外客户端请求。

### 10.6 学习页

学习页把大部分展示保持为服务端静态内容，仅控制区为客户端组件：

```text
LearnPage (Server)
├── LearningHeader
├── WordLearningClient
│   ├── WordCard
│   ├── InlineError?
│   └── NextButton
└── CompletionPanel（进度完成时替代 WordLearningClient）
```

客户端切词状态：

```ts
type LearningClientState = {
  card: WordCardViewModel;
  progressVersion?: number;
  pending: boolean;
  error?: string;
};
```

点击“下一个”：

1. pending 时忽略再次点击。
2. 提交当前 `rowId/bookId/version`。
3. `state=next`：原位替换卡片和版本，页面滚动回卡片顶部。
4. `state=completed`：显示完成面板，并刷新服务端路由数据。
5. `PROGRESS_CONFLICT`：显示同步提示并采用服务端返回的当前卡片。
6. 其他错误：保留原卡，提供重试；不得乐观增加进度。

点击单词详情使用：

```text
/word/{encodedWordId}?bookId={encodedBookId}
```

当前卡片本身不需要写入 URL；浏览器返回会恢复前一 React 页面状态。为应对页面被系统回收后重新请求，服务端会根据尚未推进的进度再次算出同一待学词。

### 10.7 单词详情

`WordDetailContent` 按以下子组件拆分，均只接收已清理数据：

```text
WordDetailContent
├── WordHeading
├── PronunciationRow?
├── TranslationSection
├── SentenceSection?
├── PhraseSection?
├── MemorySection?
├── SynonymSection?
└── RelatedWordSection?
```

- 数组使用稳定组合键；不要仅以数组下标作为可变列表 key。
- 超长英文定义和单词允许换行，避免 H5 横向滚动。
- `usspeech/ukspeech` 暂不生成音频 URL；没有可信资源基址时不渲染假播放按钮。
- 详情页不推进学习进度。

### 10.8 加载、错误和空状态

每个路由段提供相应的 `loading.tsx` 和 `error.tsx`：

| 场景 | 表现 |
| --- | --- |
| 首页加载 | 最近学习和书卡骨架，不展示错误进度 |
| 首页无书 | “暂无单词书，请稍后再来” |
| 书籍列表失败 | 模块错误 + 重新加载 |
| 学习书不存在 | 404 + 返回首页 |
| 书存在但无有效词 | 数据异常提示 + 返回首页 |
| 进度保存失败 | 卡片不变 + 行内错误 + 重试 |
| 详情可选字段为空 | 隐藏对应模块 |
| 详情核心字段无效 | 404/数据异常页，不渲染半张卡片 |

## 11. 缓存与性能

### 11.1 缓存边界

- `books` 目录和公开单词内容可以按短周期服务端缓存，例如 5 分钟；后台更新后可按 tag 主动失效。
- `learning_progress`、最近学习和“我的”列表均为用户私有数据，禁止放入无 `userId` 隔离的共享缓存。
- 调用 `auth()` 的用户页面应按动态页面处理，避免把 A 用户结果缓存给 B 用户。
- 推进或重置成功后调用对应路径/tag 的失效机制，至少覆盖 `/`、`/mine` 和当前 `/learn/[bookId]`。

### 11.2 查询与载荷

- 首页只查询书籍元数据和进度，不加载 `words.content`。
- 学习页只返回当前卡片字段；详情大 JSON 按点击加载。
- “下一个”Action 可以在一次事务后返回下一张卡，避免客户端再发一次读取请求。
- `words_book_rank_id_idx` 支持首词和下一词范围查询。
- `learning_progress_user_updated_idx` 支持“我的”排序；部分索引支持最近学习。
- 不在请求中执行全表 `count(*)`。`books.word_count` 由导入/校验流程维护，进度初始化时按需要验证有效数。

### 11.3 封面图片

- 配置 `next/image` 远程域名白名单，或通过可信图片代理加载。
- 限制原图尺寸和格式，列表使用固定比例缩略图。
- 空 URL、非 HTTPS 或加载失败统一回退本地资源。

## 12. 安全设计

### 12.1 身份与授权

- 页面中间件只改善跳转体验，所有私有查询和 Action 再次调用 `auth()`。
- `userId` 永远不从表单、查询参数或客户端状态获取。
- 详情页虽是只读，也按产品要求登录后访问。
- 学习进度更新的 `bookId`、当前单词和用户归属均在事务内校验。

### 12.2 密码与账号

- 使用现有 bcrypt，合理成本参数沿用当前 `genSaltSync(10)`；如调整成本需先做部署环境性能测试。
- 密码只在注册/登录 Action 生命周期内存在，不进入日志、埋点、错误对象或客户端持久化。
- 注册密码长度限制应按 Unicode 字符规则统一前后端口径；数据库存储的是定长附近的哈希，不以明文长度设计列宽。
- 登录错误不暴露邮箱是否注册。
- 注册依赖数据库唯一索引作为并发最终防线。

### 12.3 Web 安全

- 使用 Auth.js 自带的安全 cookie 和 CSRF 防护；生产环境强制 HTTPS。
- 对 Server Action 保持同源校验，部署代理需正确配置可信 Host。
- `returnTo` 使用白名单，防止开放重定向。
- 用户可控文本默认依赖 React 转义，禁止用 `dangerouslySetInnerHTML` 渲染词典 JSON。
- 配置合理 CSP、`frame-ancestors`、`X-Content-Type-Options` 和 Referrer Policy。
- 错误响应不返回 SQL、连接串、堆栈或原始数据库 JSON。

## 13. 数据迁移与初始化

### 13.1 迁移原则

- 引入与当前 Drizzle ORM 兼容的迁移工具，迁移 SQL 提交到 `lib/db/migrations`。
- 迁移在部署流水线中只执行一次，应用实例启动不自动修改数据库结构。
- 先审计、再清理、再加约束；大表索引需评估锁表时间，生产可使用 `CREATE INDEX CONCURRENTLY` 并从事务型迁移中拆出。
- 执行前备份数据库，并在预发布环境用生产规模副本测量耗时。

### 13.2 上线前数据审计 SQL

检查空关联和非法排名：

```sql
select id, "bookId", "wordRank"
from public.words
where "bookId" is null
   or "wordRank" is null
   or "wordRank" <= 0;
```

检查孤儿单词：

```sql
select w.id, w."bookId"
from public.words w
left join public.books b on b.book_id = w."bookId"
where w."bookId" is not null
  and b.book_id is null;
```

检查 JSON 根结构和核心字段：

```sql
select
  id,
  content -> 'word' ->> 'wordId' as word_id,
  content -> 'word' ->> 'wordHead' as word_head,
  "headWord"
from public.words
where content is null
   or json_typeof(content -> 'word') <> 'object'
   or nullif(btrim(content -> 'word' ->> 'wordId'), '') is null
   or coalesce(
     nullif(btrim(content -> 'word' ->> 'wordHead'), ''),
     nullif(btrim("headWord"), '')
   ) is null;
```

检查同一本书重复排名：

```sql
select "bookId", "wordRank", count(*)
from public.words
where "bookId" is not null
  and "wordRank" is not null
group by "bookId", "wordRank"
having count(*) > 1;
```

检查同一本书重复 JSON `wordId`：

```sql
select
  "bookId",
  content -> 'word' ->> 'wordId' as word_id,
  count(*)
from public.words
where "bookId" is not null
  and nullif(btrim(content -> 'word' ->> 'wordId'), '') is not null
group by "bookId", content -> 'word' ->> 'wordId'
having count(*) > 1;
```

检查书籍声明词数与有效词数：

```sql
select
  b.book_id,
  b.title,
  b.word_count as declared_count,
  count(w.id) filter (
    where w."wordRank" > 0
      and nullif(btrim(w.content -> 'word' ->> 'wordId'), '') is not null
      and coalesce(
        nullif(btrim(w.content -> 'word' ->> 'wordHead'), ''),
        nullif(btrim(w."headWord"), '')
      ) is not null
  ) as actual_valid_count
from public.books b
left join public.words w on w."bookId" = b.book_id
group by b.book_id, b.title, b.word_count
having b.word_count <> count(w.id) filter (
  where w."wordRank" > 0
    and nullif(btrim(w.content -> 'word' ->> 'wordId'), '') is not null
    and coalesce(
      nullif(btrim(w.content -> 'word' ->> 'wordHead'), ''),
      nullif(btrim(w."headWord"), '')
    ) is not null
);
```

### 13.3 建议迁移顺序

1. 备份并执行第 13.2 节审计。
2. 确认 `words.content` 根路径，修复或隔离无效数据。
3. 创建或正式迁移 `"User"`，清理重复邮箱后增加小写唯一索引。
4. 为 `books/words` 增加非破坏性索引和检查约束。
5. 清理孤儿数据后增加 `words → books` 外键。
6. 创建 `learning_progress`、唯一约束、外键和索引。
7. 更新 Drizzle schema 和认证代码，移除 `ensureTableExists()`。
8. 部署应用并执行冒烟测试。
9. 观察错误和慢查询后，再决定是否把现有可空核心字段收紧为 `NOT NULL`。

### 13.4 回滚策略

- 应用回滚不删除 `learning_progress` 数据；旧版本不会读取该表。
- 新增索引和表可以保留，不影响旧应用。
- 不在同一发布中执行不可逆的 JSON 大规模改写。
- 若新进度写入逻辑异常，先关闭学习入口或回滚应用，再基于结构化日志核对进度；不得直接批量清空用户数据。

## 14. 错误处理与可观测性

### 14.1 错误分类

| 类型 | 示例 | 用户表现 | 服务端行为 |
| --- | --- | --- | --- |
| 输入错误 | 邮箱格式、非法 ID | 字段级提示 | 不记 error 日志或低级别记录 |
| 认证错误 | 会话失效、密码错误 | 登录提示或打开 Popup | 不泄露账号存在性 |
| 业务错误 | 空书、已完成、进度冲突 | 可恢复提示 | 记录业务上下文 |
| 数据错误 | JSON 缺核心字段、词数不一致 | 跳过无效项或错误页 | 结构化告警 |
| 系统错误 | 数据库超时 | 通用错误与重试 | error 日志、请求 ID、监控告警 |

### 14.2 日志字段

```text
requestId
route/action
userId（服务端内部 ID）
bookId
wordRowId
progressVersionBefore/After
resultCode
durationMs
```

禁止日志字段：密码、密码哈希、完整 session token、完整单词 JSON。邮箱如必须记录，应脱敏或散列。

### 14.3 指标

- 登录/注册成功率与限流命中率。
- 首页、学习页、详情页服务端响应耗时。
- `advanceWordAction` 成功、重复、冲突和失败计数。
- 无效单词 JSON 计数、书籍词数不一致计数。
- 数据库慢查询和连接池使用率。

## 15. 测试方案

### 15.1 单元测试

`word-mapper` 使用 `ruler` 和 `pencil` 样例作为固定 fixture，至少覆盖：

- 优先使用 `content.word.wordHead`，缺失时回退 `words.headWord`。
- 卡片只取第一条有效中文释义和第一条有效例句。
- 详情保留全部例句、短语、同近词和同根词。
- `phrase/remMethod/syno/relWord` 任意缺失时返回空模块而不抛错。
- 空字符串、错误数组项和部分结构损坏的降级。
- PostgreSQL bigint 行 ID 序列化为字符串。

业务函数覆盖：

- 百分比计算和上下界。
- `returnTo` 白名单与外部 URL 拒绝。
- 新书、学习中、已完成三种进入状态。
- 非连续 rank 时基于排序元素而不是 `rank + 1`。

### 15.2 数据库集成测试

使用独立测试数据库执行真实迁移并验证：

- 邮箱大小写唯一约束和并发注册。

- 首词/下一词查询使用稳定排序。
- 最近学习只返回 `status=learning` 的最新记录。
- 同一当前词的两个并发推进请求只累计一次。
- 陈旧设备提交返回冲突，不覆盖新进度。
- 最后一词推进时原子变为 `completed`。

- 未登录不能推进或重置进度。

- Auth.js 重定向异常不会被误报为登录失败。

1. 游客打开首页，只看到全部单词书。

## 17. 关键技术决策汇总

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| 页面架构 | Next.js App Router + RSC + Server Action | 贴合现有项目，减少客户端 API 瀑布 |
| 客户端状态 | 局部状态，不引入全局 store | 服务端进度是唯一事实源，当前交互规模较小 |
| 用户表 | 保留 `"User"` 表名并正式迁移 | 最大化复用现有 Credentials 代码 |
| 会话 | Auth.js JWT session | 当前无 Adapter，MVP 无需额外 session 表 |
| 进度模型 | 每用户每书一条连续进度 | 满足顺序学习，数据量和事务复杂度最低 |
| 幂等 | 行锁 + 服务端期望当前词校验 | 抵御重复点击和多设备并发 |
| 单词定位 | 数据库 `words.id` 推进，JSON `wordId` 用于详情路由 | 主键适合事务，业务 ID 适合可读定位 |
| 单词顺序 | `wordRank ASC, id ASC` | rank 不连续或重复时仍确定 |
| JSON 处理 | 运行时解析后映射两类 ViewModel | 防止可选字段使页面崩溃并控制卡片载荷 |
| `json`/`jsonb` | MVP 保持 `json` | 当前不需要复杂 JSON 检索，避免整表重写 |
| 词库修改 | 已发布 `book_id` 内容不可原地重排 | 保证用户进度游标稳定 |
| 音频 | MVP 不实现 | 只有资源键，没有可信播放地址 |

## 18. 后续扩展边界

出现以下需求时再新增 `user_word_state` 表：

- 生词收藏、认识/不认识按钮。
- 每词熟练度、错误次数和最近复习时间。
- 间隔重复和跨书去重。
- 用户可以跳着学习或自定义顺序。

建议扩展结构：

```text
user_word_state
├── user_id
├── word_row_id
├── familiarity
├── first_learned_at
├── last_reviewed_at
├── next_review_at
└── mistake_count
```

该扩展表不替代 `learning_progress`：前者描述逐词掌握情况，后者继续负责一本书的线性入口和汇总进度。
